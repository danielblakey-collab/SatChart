# Offline MBTiles release gate

Every district, shoreline, Bristol Bay satellite, and NOAA MBTiles package must pass the release validator before it is uploaded to R2. The validator is read-only and streams tile blobs; it does not repair production files.

```sh
python3 scripts/validate_mbtiles_package.py path/to/egegik_v6.mbtiles \
  --id egegik_v6 \
  --version v6 \
  --output path/to/egegik_v6.manifest.json
```

The command validates the SQLite header and integrity, supported flat or normalized schema, coordinate uniqueness and ranges, indexed coordinate query plan, metadata, every image blob, dimensions, format consistency, bounds, zoom counts, and suspicious blob sizes. PNG raster streams are decompressed and checked. JPEG entropy data is fully decoded without re-encoding the source; install Pillow (`python3 -m pip install Pillow`) on a release machine before validating a JPEG package.

Upload both immutable files only after the command exits successfully:

- `<slug>.mbtiles`
- `<slug>.manifest.json`

The JSON SHA-256 and byte count are authoritative for that exact object. Never edit or replace a versioned MBTiles object in place; publish a new version and manifest. SatChart also accepts a trusted SHA-256 from the R2 `x-amz-meta-sha256` or `x-satchart-sha256` response header. Current legacy R2 objects remain compatible through structural validation, but are reported as lacking an authoritative remote hash until one of those metadata sources is published.

Missing `metadata.scheme` follows the MBTiles legacy TMS default. The one documented shipped exception is `egegik_v2`, whose legacy object omits the field but stores XYZ rows; the app and validator apply an explicit package-scoped XYZ compatibility rule. Do not add geographic row-distribution guessing. Republished versions should declare `scheme` explicitly.

Runtime receipts use the coordinate envelope at the highest stored zoom as the authoritative display footprint. This prevents stale metadata from clipping native tiles or expanding a district overlay to the world; a declared `metadata.bounds` box that does not even intersect the native envelope fails validation. Lower zoom ancestors are deliberately excluded from the display footprint because a z0/world ancestor must not defeat geographic request suppression.

Downloaded district maps and shoreline imagery can be enlarged beyond their native detail while Districts Offline uses MapKit’s camera range. The standalone Bristol Bay satellite offline basemap retains its camera maximum of 17. Source detail remains capped at the package’s available native zoom, at most 15. At closer camera scales a custom overlay renderer draws the validated native parent image directly into its MapKit rectangle. It does not manufacture, encode, publish, or persist a synthetic descendant pyramid.

## Runtime scheduling and budgets

The app applies one aggregate device-adaptive scheduler across active MBTiles layers. It uses two active workers and a 96-item queue on memory-constrained hardware, up to four workers and 256 queued items on modern hardware, and drops to one worker with a 48-item queue under serious thermal pressure. At most one speculative operation can run; speculation is suspended during gestures, Low Power Mode, memory pressure, and fair-or-worse thermal pressure. The separate online Bristol fallback is capped at 1/2/3 concurrent network, read, and crop operations on constrained/moderate/modern hardware so it cannot overwhelm an older device while district MBTiles are active. A separate bounded serial ingress keeps MapKit request closures from accumulating ahead of the scheduler. The scheduler ranks current-zoom tiles nearest the viewport center first and lets higher-priority visible work displace lower-priority queued work rather than rejecting the visible request. Within the highest available priority tier it rotates among least-recently-served package owners, preventing a busy district from starving another visible district or shoreline. Every rejected, displaced, cancelled, or completed request receives exactly one terminal callback.

Downloaded district, shoreline, and offline Bristol Bay packages use a retained, non-replacing renderer as their sole raster painter. The MKTileOverlay remains attached as the package/lifecycle anchor, with an empty renderer so transparent pixels are not painted twice. It is attached with the package and draws at every scale from a retained overview and the last complete viewport image set. Loading or evicting destination tiles cannot discard those pixels. A complete new viewport replaces the old one only after every tile resolves to an image or a confirmed missing tile; transient failures retain the old frame. Online districts and the online Bristol Bay background use the same renderer through their existing bounded tile store. Replacement versions retain the last-known-good renderer until every ordinary tile at lower scales—or every native parent while overzoomed—covering the current clipped viewport has reached a terminal image-or-missing result. Camera changes restart that exact-viewport check; transient failures use a capped exponential-backoff chain, so recovery does not require the user to zoom. After a viewport settles, the current and approaching zoom are prefetched with a one-tile border, center-first and below visible work. Prefetch is disabled during interaction; a throttled 75 ms center/zoom hint is the only MBTiles work on the continuous camera callback. Do not set `canReplaceMapContent` for sparse raster packages: legitimate coverage gaps must reveal the next valid backing layer.

Each immutable package session uses one serialized read-only SQLite reader with a 2 MiB page-cache target and memory mapping disabled. Only configuration and compressed-byte lookup occur under that serialization lock; raster validation, ancestor decoding/cropping, encoding, and district appearance filters use the bounded worker pool outside it. Lazily loaded per-zoom column bounds skip SQLite work for coordinates that cannot exist while avoiding a full-package scan during first-tile startup and preserving normal sparse-package misses inside those bounds.

Each visible raster source additionally pins at most 16 overview thumbnails (128 px) and 48 detail tiles (256 px), plus one bounded loading generation: at most approximately 25 MiB of retained/loading image pixels per source, plus up to 12 MiB for the frozen visible frame during movement. This ownership is separate from the evictable LRU cache so cache pressure cannot create a blank zoom buffer. Sources that have not intersected the viewport do not load an overview. Planning reduces the requested pyramid level until the whole requested area fits the tile cap, before enumerating coordinates. Overview pixels are clipped out wherever detail tiles take over, and both use normal alpha compositing. Never use copy/clear against MapKit's drawing surface: that erased the backing map inside Egegik's rectangular tile footprint. A renderer freezes its current image set during camera movement and defers/coalesces incoming invalidations until settling. It then invalidates only the changed footprint, rather than every buffer for the entire overlay. Drawing only composites retained images; database access, decoding, and network work remain off the draw path.

The +/− buttons preload the target footprint for up to 350 ms before moving the camera. Readiness can shorten the wait; failures use the timeout with retained imagery. New button requests supersede old ones, and camera movement, mode/version/appearance changes, and teardown cancel stale requests. Pinch gestures stay immediate.

The shared deterministic O(1) LRU caches are device-adaptive. Constrained hardware starts at 16 MiB compressed source bytes, 4 MiB generated bytes, 6 MiB decoded source images, 12 MiB continuity images, and 1,024 negative entries; modern hardware starts at 32/8/10/16 MiB and 2,048 negatives. Durable Low Power and thermal states shrink those limits, while gestures do not churn the continuity cache. Decoded images are costed by allocated bytes. Raw source identity is separate from appearance output identity, so brightness/contrast/gamma/saturation are applied once and adjusted output can never poison the neutral source cache. At most eight inactive package sessions are retained. Memory warnings cancel speculative work, clear generated/negative data and decoded source images, retain only a small most-recent continuity set, and trim compressed bytes; admitted visible work still finishes.

Debug diagnostics expose queue saturation, displaced and stale-cancelled requests, coverage-envelope rejections, active cache identities, and rolling P50/P95 queue, SQLite, raster, and total-request timings. Use those measurements to distinguish database latency from image-generation latency before changing worker or memory limits.

## MapKit interaction and layer identity

`mapViewDidChangeVisibleRegion` is intentionally a constant-time fast path. It advances camera-movement state and, no more often than every 75 ms, passes lightweight center/zoom generation hints to already-attached package sessions. It must not publish SwiftUI state, reconcile overlays, mutate renderers, change opacity, run prefetch, or perform file/database/image work. This hint prevents destination requests queued during a long pan from being stamped as the old viewport and cancelled at settle. `regionDidChangeAnimated` consumes the latest movement generation once and performs the coalesced scale, marker, basemap, and settled viewport update.

Overlay identities contain the physical package generation and every value that changes returned tile bytes, but never presentation-only opacity or camera state. Unchanged overlay objects retain the same cached renderer. Renderer opacity is normalized and clamped, is changed only on the main actor, and uses an epsilon of `0.001`; equal values and camera movement perform no `alpha` write. The conditional context-alpha workaround is not enabled because SatChart's audited camera path did not contain an alpha assignment and no SatChart-specific reproduction justified replacing MapKit's normal opacity behavior.

For `Districts Offline`, preserve this raster order from back to front: Apple Satellite worldwide; the downloaded Bristol Bay Satellite Offline package within its validated bounds, or the bounded online Bristol Bay layer only when no downloaded package exists; then the selected downloaded district and applicable shoreline packages; then SST and other live overlays. Missing Bristol Bay or district pixels remain transparent so the next valid backing layer shows through. No sparse raster overlay replaces MapKit's base content.

DEBUG map-stability counters cover SwiftUI map updates, continuous callbacks, movement intervals, settled updates, reconciliation duration, overlay mutations, renderer construction, reload calls, opacity attempts/writes, programmatic camera applies/skips, and main-thread violations. Logs are aggregate-only and must not include coordinates, vessel movement, radio identities, or waypoint data.

Coverage-gap counts are informational by default because district and shoreline imagery has legitimate sparse/concave AOI edges. For rectangular packages that are expected to be internally complete, add `--fail-on-hole-candidates` and review any failure before release.

The iOS installer downloads to `Library/Application Support/OfflineMaps/.staging`, validates off the main thread, moves the complete bundle into an immutable version directory, then atomically replaces `active.json`. Hashing checks cooperative cancellation each MiB. Cancel and descriptor publication share an atomic commit authorization, deletion drains every package session and preview-file lease before unlinking, late URL-session callbacks are operation-scoped, and background completion waits for activation. A failed, cancelled, or interrupted staging operation cannot replace the previous active version.


### Egegik transparency and zoom regression

`EgegikRasterRegressionTests` uses unmodified zoom-11 and zoom-12 tile bytes from the published Egegik v4 MBTiles and XYZ pyramids. `Fixtures/egegik-fixture-provenance.json` records the XYZ tile hashes. The backing-surface tests fail on the prior copy/clear renderer (158,151 damaged pixels offline and 159,332 online) and require zero damaged pixels after the change. Additional checks load sharper actual tiles during movement, assert no mid-gesture image change or invalidation, and sample the real shoreline in live MapKit while tiles arrive. The solid-red tests alone do not cover this failure mode. Physical-device pinch and low-memory behavior still need device verification.
